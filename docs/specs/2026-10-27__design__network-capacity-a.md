# A 模型深度与宽度容量实验

日期：2026-10-27。状态：arm/wheel=0.8/0.2。用户授权的[单独D8-W256训练与评估](../reports/2026-10-27__report__d08w0256-single-run.md)已完成，单LR3e-4、seed0、84k；下述30组完整矩阵仍待后续确认。

用户目标：先训练多种深度和神经元数量的网络，检验当前网络容量是否限制了复杂控制的学习。用户已确定先做 A，验证后再考虑 B。下列架构矩阵、预算和评估规则由本次方案提出，尚未冻结为实验协议。DAgger 暂列在本轮容量实验之后。

本轮承接[原baseline训练plan](../plans/2026-10-26__plan__mlp-baseline-training.md)及[训练配方研究](../research/2026-10-26__research__mlp-training-recipe.md)，复用现有`training/common/engine.py`训练循环。用户补充要求沿用Adam系列优化与学习率方法、数据统一采用Clean_253；以下明确这两项。

## 要回答的问题

在相同 A 专家数据、特征、优化与评价条件下，更深或更宽的 MLP 是否改善 reaching 拟合，以及学生自己执行训练场景时的 reaching/保持成功率。上一轮 A M6 BC+J 在 fitting 场景上仅 1/221 持续保持成功，因此本轮不能只报告训练 loss；也不预先把容量不足认定为唯一根因。

最新的[已有网络0.8/0.2重训](../reports/2026-10-27__report__arm08-wheel02-retraining-a.md)已完成：六组BC配对验证均0/32 reach，M6 BC+J为1/32 reach，所有模型0/32持续保持。本轮在相同0.8/0.2权重下比较容量，主对照仍从头训练M6，以统一学习率搜索和84k日程。

## 方法选择

采用等宽 MLP 的完整深度×宽度网格，配对训练预算和学习率搜索预算。它直接对应用户要检验的深度、神经元数量，复用当前 `Linear → LayerNorm → SiLU` 和双输出头；新增更复杂的网络类型会另引入结构因素，不属于本轮主比较。

不采用按早期成绩逐级淘汰作为主比较：慢收敛的深网络可能在预算不足时被提前剔除。所有有效任务都执行相同的预定优化步数；若发生非有限训练或显存错误，显式记录该配置失败，不自动改变配置后仍并入原比较。

## 网络矩阵

深度仅指隐藏层数量；每层均含 Linear、LayerNorm、SiLU，输出头不计入深度。A 输入 21 维，输出头为 7 个力矩与 2 个独立轮速，部署时展开为原 11 维动作。

| 架构 ID | 隐藏层 | 参数量（含 LayerNorm 与输出头） | 相对 M6 |
|---|---|---:|---:|
| m6 | `[256,128,64]` | 48,265 | 1.0× |
| d03w0256 | `[256] × 3` | 141,065 | 2.9× |
| d03w0512 | `[512] × 3` | 544,265 | 11.3× |
| d03w1024 | `[1024] × 3` | 2,137,097 | 44.3× |
| d05w0256 | `[256] × 5` | 273,673 | 5.7× |
| d05w0512 | `[512] × 5` | 1,071,625 | 22.2× |
| d05w1024 | `[1024] × 5` | 4,240,393 | 87.9× |
| d08w0256 | `[256] × 8` | 472,585 | 9.8× |
| d08w0512 | `[512] × 8` | 1,862,665 | 38.6× |
| d08w1024 | `[1024] × 8` | 7,395,337 | 153.2× |

`d03w0256` 与旧 M5 结构相同，是等宽网格内的既有架构参照；不能把它描述成新的结构。增加深度同时增加参数量，因此该网格支持“固定宽度增加层数”的比较，不单独证明固定参数量下的深度优势。

## 固定项与首阶段预算

- 教师 A：`markovian-lt0.50-v1`；Clean_253 的原 221 个 fitting 轨迹、32 个 validation 和 8 个 screening，均沿用 `experiments/splits/clean253.json`，验证/测试数据不进入拟合。
- 保持 21 维特征、物理参数、1000 Hz 接口、±30 N·m 和 ±6 rad/s 执行限制。归一化仅由同一 fitting 数据和原尺度下限确定，核对所有架构得到同一归一化内容哈希。
- 所有模型从头初始化，采用现有 PyTorch Linear 默认初始化、LayerNorm 初始化与独立 init RNG stream。首阶段 seed0；不同结构的相同 seed 不等于权重逐元素相同。
- 主比较使用纯 BC：标准化 Huber，delta=1，总损失 `0.8 × mean_arm + 0.2 × mean_wheel`，每组分别先取均值。所有架构及M6对照统一使用这组权重，并将其写入配置与任务身份。Jacobian 损失组合不混入本次容量主结论；已有 A BC+J 仅作历史结果参照。
- AdamW，weight decay `1e-4`，batch 1024，原“均匀抽轨迹、再均匀抽该轨迹时间点”的采样方式。
- 所有架构各跑 LR `{1e-3, 3e-4, 1e-4}`，warmup 500 updates，随后 cosine 至 **84,000 updates**。每个模型约 32.36 个等效采样 epoch；主横轴仍为 update。
- 首阶段合计 **10 架构 × 3 LR × seed0 = 30 次完整训练，252 万 optimizer updates**。这包含重新训练 M6 对照，不以旧 42k 训练代替 84k 对照。
- 固定比较节点为 42k 与 84k。当前任务的 42k 节点使用 84k cosine 日程，不能把它与历史 42k cosine 任务当成只改变网络的配对实验。
- 每 2000 updates 记录离线指标，每 7000 updates 保存 checkpoint（包含 42k 和 84k），保留可恢复的 `latest.pt`。同一科学配置的 resume 必须匹配原配置、数据与哈希。

### 与原训练plan对应的优化与数据设置

| 项目 | 本轮明确采用的设置 |
|---|---|
| 数据版本 | `identity.cohort=clean253`，教师A数据源`data/Markovian/Clean_253` |
| 数据划分 | 原`clean253.json`：221条fitting用于梯度更新，32条validation独立评估；8条screening来自validation子集 |
| 数据处理 | 仅fitting估计标准化；保留原特征与逐轨迹均匀采样，全部架构使用同一数据、划分与归一化 |
| 优化器 | 原实现的AdamW：`betas=(0.9,0.999)`，`eps=1e-8`，`weight_decay=1e-4` |
| 基础学习率 | 每种架构各训练`1e-3`、`3e-4`、`1e-4`，分别产生独立run |
| 全局学习率日程 | 前500次更新线性warmup至该run的基础学习率；随后cosine衰减至84,000次更新结束，末端接近0 |
| batch与训练预算 | batch1024，所有30组均84,000次更新，从头初始化；42k/84k均保留比较结果 |
| 损失 | 标准化Huber，δ=1，`0.8 × mean_arm + 0.2 × mean_wheel` |
| 恢复训练 | 原latest机制同时恢复模型、AdamW状态、学习率scheduler和RNG；必须属于同一配置 |

AdamW按梯度的一阶/二阶矩对各参数自适应调整更新，warmup与cosine控制整个训练过程的基础学习率，两者同时使用。Clean_253的253指数据版本及其训练轨迹总量；本轮仍遵守原plan的221/32内部划分，以保留独立验证依据。容量预算84k与本轮权重0.8/0.2是相对旧baseline配方的明确变更，其余优化方法沿用；本轮在每种架构的三个LR及42k/84k节点上做screening，选择规则见下一节。

首阶段不自动扩展 seed1/2 或 BC+J。它们在首阶段报告后作为独立下一阶段；多 seed 是检验结论稳健性的必要后续，seed0 筛选不能宣称统计上稳定的架构优势。

## 模型选择与物理评价

每个架构的 3 个 LR，在 42k/84k 两个节点上各跑原 8 场景 screening，共 6 个候选。按原规则选择一个：持续保持率高、reach 率高、最终误差中位数低、饱和/动作变化低，最后较早 checkpoint 优先；完全同分时按 LR 数值较小优先，保证选择确定。42k 与 84k 的固定节点结果也都保留，不只展示最优节点。

然后每个架构的唯一选中候选都执行完整 32 个 validation，以及一套冻结的 32 个 fitting 场景。fitting 子集在训练前按原 2 距离×4 高度×4 方位分格，从各格 fitting ID 中取字典序最小的一个；要求每格存在 fitting 场景，禁止按模型成功与否挑选。这套子集只做训练任务诊断，不用于挑 checkpoint、LR 或验证赢家。

按完整 validation 排序选出的前两个架构，以及 M6 对照，最后各自对全部 221 个 fitting 场景评价。已评价的同一 artifact/场景可复用经过身份与配置哈希核验的结果，其余补齐，不能将重复运行算成独立场景。

纯学生闭环使用原谓词：t>8 s 且真实末端误差<10 mm 为 reach，继续运行 3 s，最终 1 s 的全部 1001 个观测均<10 mm 才算持续保持；上限 40 s。另报任意时刻进入 10 mm 的次数、最终误差、饱和与运行异常。所有成绩均由学生独立控制，不执行专家接管。

不使用任何 test 结果选择模型。原 64 个 test 已查看，不能重新声称是本轮未接触的泛化证据；本轮输出训练/验证结果，新的独立测试协议留待配方最终冻结后再制定。

## 要保存的曲线和结果

每个架构/LR 保存：学习率，batch 训练 loss，固定 fitting 探针与 validation 探针的同口径 Huber/物理 RMSE；按 navigation/approach/hold 分阶段误差；终端训练误差、数值异常与训练耗时。两个固定探针在启动前各自从每条轨迹等距取 64 行（包含首末行），保存索引哈希，不按当前模型误差选取；每个 episode 同权，保证 train/validation 曲线归约口径一致。探针指标每 7000 updates 利用现有 checkpoint callback 记录。现有完整 validation 离线指标继续每 2000 updates 记录，不将采样探针的 64 行误当成真实末尾 1 s 窗口计算 hold bias。

跨模型提供参数量、隐藏层列表、优化节点、LR 与模型文件哈希；在固定 42k/84k 节点比较离线指标和 screening，再提供选中 artifact 的 fitting/validation reach、hold 和误差。若容量增加只降低演示轨迹上的 loss、未改善学生任务成功，应明确报告这种分离。

新增输出归入独立容量实验目录：`checkpoints/capacity/2026-10-27__experiment__arm08-wheel02/clean/A/bc/<run_id>/`、`results/capacity/2026-10-27__experiment__arm08-wheel02/clean/A/bc/<run_id>/`，汇总写容量实验自己的索引。原模型、数据、协议和 demo 推荐均保留。人读文档与结果图表使用日期与类型命名；实验 run_id 继续包含架构、LR、seed、配置哈希。

## 计算预检和实现边界

刚完成的0.8/0.2重训已确认 RTX 5070 Ti Laptop GPU、约12 GB显存可用；CUDA执行需要在允许GPU访问的环境中运行。本轮必须用 `training.device=cuda`，正式启动前在实际执行环境运行现有 CUDA kernel 检查，并对最大模型做显存/吞吐预检。不得静默退回 CPU；预检失败时记录原因，处理后再启动正式矩阵。

先测各架构的训练 updates/s、最大模型 batch1024 的峰值显存和磁盘占用，再给出墙钟时间估算。现有工作盘约 92 GB 空闲。发生 OOM 时不在原配置下偷偷减 batch；应诊断或明确产生新协议。测量部署 NumPy 后端单步推理延迟 p50/p95/p99，大网络能以 1 ms 仿真步长执行，不等于能在真实机器上达到 1 kHz；两种能力分开报告。

实现复用 `training/common/models.py`、`engine.py`、`normalisation.py`、BC loss 与 evaluator。拟新增一个薄的 `experiments/capacity.py` 调度入口和日期命名的容量实验 manifest，负责架构注册、任务身份、checkpoint 节点和结果汇总；不重写数值训练循环，不把旧 `experiments.run` 的 M1–M6 全局矩阵换成新默认值。记录新调度器和 manifest 的源码/配置哈希。

设计已按 brainstorming 的 builder-check 要求完成独立只读审阅，未发现需要新增关键假设的问题；这不代替用户对架构、预算与启动训练的确认。

架构与预算校验必须拒绝空层列表、非正整数/布尔宽度、不合法 ID、重复任务与与数据不匹配的 resume。相关测试覆盖模型参数量、唯一身份、完整 30 任务、无 test 访问、固定 fitting 子集、失败任务保留和标准推理导出，并运行原 clean 流程回归检查。
